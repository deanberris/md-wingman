# File and track issues

All md-wingman work is tracked in GitHub Issues on `deanberris/md-wingman`. Each piece of work gets an issue before or
as the work starts, and its PRs link to it.

## Before filing

Search open and closed issues for a duplicate (`gh api -X GET search/issues -f q='repo:deanberris/md-wingman <words>'`,
or the GitHub tools you have). If one exists, comment on it or reopen it instead.

## Writing the issue

- Title: what should be true when it is done, in plain words ("Findings survive undo and redo", "Fix Safari export
  button"). No prefixes like "feat:".
- Body: what the person asked for or what goes wrong, in their words where possible; for a bug, the steps, what happened
  and what was expected, with log lines from `~/Library/Logs/md-wingman/md-wingman.log` if relevant (never document
  text, keys or tokens). Then a short task list of the parts.
- Larger work: one parent issue with sub-issues for the steps. The roadmap is issue #1.
- End anything you write on GitHub with:

```text
---
_Generated by [Claude Code](https://claude.ai/code)_
```

## While working

- Reference the issue in the PR body (`Part of #N` while more PRs are coming, `Closes #N` on the last one).
- Tick the issue's task list as parts land, and close it (reason "completed") when the last PR merges. Close as "not
  planned" only when Dean decides not to do it.
- Dean's standing rules: stack PRs and keep going; merge each PR yourself once CI is green, without waiting for him.
  Never merge a PR whose checks fail, and never push a release tag (see `cut-release`).
